Virtualizing Memory:
- Efficiency: Use hardware of hardware support
- Control: OS ensures that no application is allowed to access any memory but its own
- Flexibility: Like programs to be able to use their address spaces in whatever way they would like
	- Make system Easier to program

Crux: How to Efficiently and Flexibly Virtualize Memory?

Address Translation: Hardware transforms each memory access, changing the virtual address provided by the instruction to a physical address where the desired information is actually located
- Performed on each and every memory references 
- Both OS and Hardware are used
	- OS is to actually manage the memory (resource manager) keeping track of locations that are free and which are in use
	- Hardware for low level mechanism

Assumptions
- User's address space must be placed contiguously in physical memory
- Size of address space is not too big
	- Less than size of physical memory
- Each address space is exactly the same size

Dynamic (Hardware Based) Relocation
- Introduced first in the late 1950s as base and bounds
	- Two hardware registers within CPU
		- Base Register
		- Bound Register
	- Each program is written and compiled as if it is loaded at address zero 
		- When program starts running the OS decides where in the physical memory it should be loaded and sets the base register to that value 
			- Example 32 KB
			- Any memory reference then is translated `physical_address = virtual_address + base`
		- Each memory reference generated by the process is a virtual address
			- Hardware adds contents of the base register to this address
	- Bound register to help with protection 
		- Processor will check that a memory location is within bounds
		- If process generates a virtual address that is greater or equal to bound, or less than 0, CPU raises an exception 
	- Base and Bound Hardware structure kept on the chip (1 pair per cpu)
	- Called Memory Management Unit (MMU)
	- Register holds size of address space and hold the physical address at the end of the address space
		- Hardware adds base and makes sure its within bound
- Happens at runtime 

Software Based Relocation
- Static Relocation
	- Piece of software known as the loader takes an executable that is about to be run and rewrites its address to the desired offset in the physical memory
- Does not provide protection
	- Process can generate bad addresses

Operating Systems Issues:
- OS must take action when a process is created, finding space for its address space in memory
	- Works given our assumption
	- View physical memory as an array of slots and track whether each one is free or in use
	- Search free list
- OS must do some work when a process is terminated (exit gracefully)
	- OS Puts Memory back on the free list and clean up any associated data structures as need be 
- OS perform few additional steps when context switching 
	- Save and restore base and bounds register
	- Load base and bound pair when it switches between process as there is only 1 pair of register per CPU 
		- Save base and bound to memory in some process structure
	- When a process is stopped, it is easy for OS to move an address space from one location in memory to another
		- OS deschedules the process
		- OS copies address space from the current location to the new location
		- Updates base register to point to the new location
		- When process is resumed, its new base register is restored and begins running again
- OS must provide exceptional handlers
	- Installs these handlers at boot time
	- If raised likely terminate offending program
